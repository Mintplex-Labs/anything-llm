# Provider Failure Playbook

local wiki/reference layer — local mini operator handles provider failures locally. No provider is required for basic help.

## OpenAI Key Missing

State: OpenAI/GPT is not configured.

Action: Open Settings and add the user's own key only if live GPT replies are wanted. Keep using local wiki/reference layer for local app help.

## OpenAI Request Failed

State: OpenAI/GPT request failed.

Action: Check Offline Mode, endpoint URL, model name, key presence, and network availability. Do not print or log the key. Fall back to local wiki/reference layer.

## Grok/xAI Missing

State: Grok/xAI is not configured.

Action: Explain Grok/xAI is optional alternate provider support. It is not required and is not automatically routed in browser-first alpha.

## Ollama Unreachable

State: Local Brain/Ollama cannot be reached.

Action: Confirm Ollama is installed separately, running, reachable at the configured local URL, and not blocked by local/offline settings. Current DIZ/SWARMSY local-user behavior is browser/desktop local-first; do not assume old-app networking.

## No Models Found

State: Ollama is reachable but no model is available.

Action: Ask the user to start or pull a model in Ollama, then recheck Local Brain settings.

## Codex Not Connected

State: Codex is not connected.

Action: Explain Codex is a future code repair/build lane. Prepare a repair request with logs, reproduction steps, and expected behavior, but do not claim an automatic connection.

## GitHub Not Connected

State: GitHub is not connected.

Action: Explain GitHub is a future issue/PR/review lane. Do not request or display tokens in chat or diagnostics.

## All Providers Unavailable

State: no live provider is available.

Action: Use local wiki/reference layer — local mini operator. Search local docs/current truth/QA docs, explain provider status, and offer the next safe local action.
