# Source Refresh Protocol

## Official Source Preference
1. Root canon files (`README.md`, `STREET_SWARM_FINAL_MEGA_BUILD_TRUTH.md`)
2. Current truth (`docs/STREET_SWARM_CURRENT_TRUTH.md`)
3. Brain safety and source-card layers (`docs/brain/safety`, `docs/brain/source_cards`)
4. Runtime/sync technical docs (`docs/brain/runtime`, `docs/brain/sync`)
5. Historical/documentary archives
6. Sandbox enhanced-copy layers

## Refresh Cadence
- Weekly: runtime routing notes, ingestion/sync behavior notes, provider constraints
- Biweekly: source cards tied to platform policies or legal boundaries
- Monthly: history/documentary context and product playbooks
- Immediate refresh: if a law/platform rule materially changes

## High-Risk Topics Requiring Fast Refresh
- law, compliance, and campaign legality boundaries
- platform policy shifts
- misinformation/propaganda and influence-pattern analysis
- fake engagement and social-proof abuse detection
- any guidance that could drift into operational wrongdoing

## No-Stale Law / Platform Rule Guidance
- Never present stale legal/policy guidance as current operational truth.
- If freshness is uncertain, mark the guidance as needing revalidation.
- Route users to documentary/analytical framing, not operational wrongdoing instructions.
- Preserve lawful transformation doctrine: store public knowledge, transform patterns, output lawful creative mechanics.

## Ownership and Trigger Process
- Owner: repository maintainers and documentation reviewers on Street Swarm canon/brain updates.
- Trigger events: legal/policy changes, moderation-rule updates, major provider/runtime behavior changes.
- Process: update affected source cards/protocol docs, note refresh in PR summary, then re-run retrieval readiness checks.
