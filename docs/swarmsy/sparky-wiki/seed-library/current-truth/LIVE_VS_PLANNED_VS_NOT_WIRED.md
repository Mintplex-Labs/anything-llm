# Live vs Planned vs Not Wired

## Purpose

Separates implemented features from planned specs and not-wired ideas.

## Status label: Docs/spec only

This is optional SPARKY Wiki reference knowledge. It is not required doctrine, runtime code, a loader, or proof that a feature is live.

## Category

Current Truth

## When Sparky should use this file

- When comparing documentation claims to actual workspace/runtime state.
- When answering user questions about what Sparky or SWARMSY can currently do.

## What Sparky must not overclaim

- Do not call docs/spec features live.
- Do not describe readiness checks as generation or delivery.
- Do not imply planned Local User features are available in hosted/admin mode.

## Practical usage examples

- Answer “this is planned, not wired” for a documented route that has no implementation.
- Describe a readiness checklist as a checklist, not an image-generation engine.
